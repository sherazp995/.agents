# Review delegation when the lead cannot spawn agents

Read this in Codex for Cohabit reviews and general-review PR batch mode, or on any host whose subagents cannot spawn agents. This changes scheduling only: preserve the calling skill's lenses, pinned revisions, proof requirements, ledger ownership and cleanup. Claude hosts with permitted nested delegation keep their existing Agent workflow. A lead forbidden to spawn children uses this path on either host.

The top-level session owns every agent. Use the available native collaboration tools (Codex: `spawn_agent`, `followup_task`, `send_message`, `wait_agent`). Do not invent Claude's `Agent`, `TaskOutput`, `run_in_background`, model aliases or tool arguments. Use fresh context (`fork_turns: "none"`) for review agents. Use available reviewer models and record any substitution; a same-model reviewer never counts as an other-model opinion. Bound active agents to the host's available slots, running lenses in waves when necessary. Subagents must not start subagents or recursive review workflows.

## Prepare, review, collect

1. Start one fresh lead with the fully substituted lead prompt and `DELEGATION: coordinator-owned; PHASE: prepare`. It performs only worktree/context steps 1 and 2 and required environment discovery. It writes one fully substituted prompt per lens to its work directory, including the senior engineer prompt, plus a short handoff naming the pinned base/head, worktree, diff, purpose, prompt paths and owned resources. It does not launch reviewers, run proof tests, write a verdict or ledger, or clean up. Return the handoff to the coordinator. The diff-only prompt, when required, contains only the diff and that lens's instructions, never purpose or other findings.
2. The coordinator starts only the native lens reviewers as fresh sibling agents: simplicity, architecture and thermonuclear for Cohabit; add diff-only for general-review batch mode. Exclude the senior engineer prompt here; step 3 exclusively owns that reviewer. Each returns findings to a separate file in this run's work directory and a short completion receipt. Tell reviewers not to edit the reviewed source or launch other agents. Preserve the source tags and the calling skill's evidence standards.
3. The coordinator also starts the other-model senior review using `general-review/references/codex-handoff.md`, relative to the shared skills root. For a Codex host use the Claude runner's second-opinion workflow; for a Claude host use the documented Codex CLI. Retain its managed terminal session and collect it as `workflow-runner/SKILL.md` specifies. Keep the same pinned scope, run ownership and no-recursion restriction. Give the senior prompt the calling skill's severity/report vocabulary. No second launch from the lead. Tests belong to the lead, so this senior pass may remain read-only. Record any unavailable reviewer explicitly rather than claim full independent coverage.
4. While reviewer slots permit, resume the lead with `PHASE: test` to run only step 4. It returns command results without cleanup or final verdict. If the host lacks resumable agents, start a fresh lead with the original substituted prompt and preparation handoff; it must reuse the recorded resources, never recreate worktrees or reset the scope. Run sequential waves when concurrency slots are exhausted.
5. Collect every reviewer and test result, including failures. Resume the lead with `PHASE: finalize`, exact report paths and missing-reviewer limitations. It performs merge, re-proof, report/record and cleanup steps from the original prompt. It must not launch reviewers, repeat preparation, or claim an absent lens ran. A missing required lens makes the review incomplete under the calling skill's rules. Keep the worktree until all readers have finished.
6. The coordinator spot-checks and publishes according to the calling skill. Wait for this run's cleanup, collect all output, then release only its acquired locks. A status question does not end collection. If interrupted, recover recorded sessions and artifacts before starting duplicates.

This path uses native sibling agents, not an extra script passed to the workflow runner. Its script allowlist stays unchanged.
