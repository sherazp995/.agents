# Relay P0.4 Capability Registry, Policy Engine, Approvals, Kill Switch

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nothing dangerous happens without a decision. Every action is classified, allowed, denied, or asked; sensitive work waits for a human in Slack; and one command stops everything within five seconds.

**Architecture:** A capability registry is the single source of truth for what exists and how risky it is. A policy engine turns a proposed action plus its context into `allow`, `deny`, or `ask`, failing closed on anything unmatched. Approvals surface as Block Kit buttons in the originating thread and default to deny-and-pause on timeout. The kill switch is a separate, always-reachable path that does not queue behind the work it stops.

**Tech Stack:** Everything from P0.1 through P0.3. No new runtime dependency expected.

## The consequence this milestone was warned about

`docs/decisions/open-questions.md` DEC-1 records it: the engine is headless Claude Code, a subprocess, not an in-process SDK. It offers **static `--allowedTools` plus `PreToolUse` hooks**, not a programmatic permission callback that can pause one tool call and await a decision.

So per-tool-call approval needs a hook that **calls back into Relay and blocks** until a human answers in Slack. That is the single hardest thing in this milestone and Task 5 owns it. Read DEC-1 before starting it.

Relay's own capabilities, the ones in its registry, are mediated in-process and are much simpler. Do not confuse the two paths.

## What P0.3 leaves behind, and what changes because of it

- **Cost is now a measured problem, not a theory.** A trivial reply cost $0.94 before session resume and $0.04 after. `--max-budget-usd` exists and nothing uses it. FR-POL-7's spend caps are therefore in scope here rather than deferred to phase 1.
- **`isKnownSession`, the drain, and unmapped-principal suppression are all wired.** Assume a working orchestrator.
- **Two P0.3 items remain open** and are not this milestone's job: the shutdown path has no automated test, and if High 4's recovery write itself fails the run row stays non-terminal.

## Global Constraints

Copied verbatim from `docs/specs/2026-08-08-relay-requirements.md` v1.10.

- **AP-1:** within a governed run, the model never touches a raw capability; every tool call is mediated by the policy engine. Attached sessions are a separate trust boundary this principle does not cover.
- **FR-POL-2:** policy is validated on load; an invalid file fails closed and prevents startup, never defaults permissive.
- **FR-POL-3:** the default for anything unmatched is `ask`, never `allow`.
- **FR-POL-4:** the hard-blocked list cannot be overridden at runtime. Changing it requires a config edit plus restart. **No approval button may authorise a hard-blocked action.**
- **FR-POL-8:** blast radius escalates the tier. Item count, reversibility, monetary amount, and recipient breadth all raise it.
- **FR-POL-9:** the kill switch stops all runs, releases locks, aborts in-flight calls, and refuses new work, **taking effect mid-action within five seconds**.
- **FR-APR-3:** timeout defaults to **deny-and-pause, never proceed**.
- **FR-APR-4:** only principals holding the approval role for that tier may resolve an approval.
- **FR-APR-5:** the highest-severity actions require typed confirmation, not a single click.
- **FR-APR-10:** a paused run posts an explicit "waiting on you" summary. A paused run must never look like a working one.
- **FR-SEC-1, FR-SEC-2:** no secret in any log, error, or database column. Credentials brokered.
- **AP-5, AP-8, FR-RPT-10, NFR-10, NFR-11** as before.
- **Rule 45:** no dash as sentence punctuation in prose, including comments and commit messages.
- **Never `git add -A`.** Stage explicit paths. **Confirm a clean tree and that the verdict's fixes are in `HEAD` immediately before tagging**, which P0.3 failed to do.

## Lessons this plan encodes, each paid for

- **A test count that does not move is a red flag.** Every task reports it before and after.
- **Prove a guard by removing it.** Every task names a self-attack.
- **Test through the path production uses, not the mechanism in isolation.** P0.3 shipped a cancellation measured at 2ms that nothing could reach from Slack. A policy engine that only unit tests will do the same.
- **Do not overstate coverage.** State what you did not cover.
- **Run the real artifact**, and check `git status` before claiming anything is done.
- **Ask when the plan is wrong.** Every implementer who asked here found a genuine defect.

### Task 1: Capability registry with risk tiers

**Files:** create `src/capabilities/registry.ts`, `test/capabilities/registry.test.ts`. Modify `src/agent/capabilities/echo.ts` to register itself.

**Produces:** `registerCapability(def)`, `getCapability(name)`, `listCapabilities()`, and the `CapabilityDefinition` type carrying name, description, input schema, output schema, **risk tier**, **idempotency class** (`safe` / `idempotent` / `mutating` / `irreversible`), required runner features, and cost hint.

**Requirements:** FR-CAP-1 to FR-CAP-5.

Tests must prove: a capability cannot be registered without a tier and an idempotency class; the model's tool list derives from the registry rather than being maintained separately, so the two cannot drift; an unregistered capability is refused rather than defaulted; and `echo` registers as `safe` / `read`.

**Self-attack:** register a capability with a missing tier and confirm it is refused.

---

### Task 2: Policy classification and decision, pure

**Files:** create `src/policy/schema.ts`, `src/policy/classify.ts`, `src/policy/decide.ts`, and their tests.

**Requirements:** FR-POL-1 to FR-POL-4, FR-POL-8.

`classify` takes a proposed call plus context and returns a tier, applying the **escalation rules**: destination not on the allowlist, monetary amount above a threshold, affected-item count above a threshold, a credential in the arguments, and first contact with an origin. `decide` maps a classification plus policy to `allow`, `deny`, or `ask` with a **reason string**.

Both are pure so they are exhaustively testable without a database.

Tests must prove: a table-driven suite over every tier and escalation rule, including boundaries; **an unmatched action returns `ask`, never `allow`**; a hard-blocked destination returns `deny` and **no policy setting or approval can turn it into `allow`**; a `write` on an unknown origin escalates to `sensitive`; blast radius escalates by count and by amount.

**Self-attack:** make the unmatched default `allow` and confirm tests fail; make a hard-block overridable and confirm tests fail.

---

### Task 3: The mediation seam

**Files:** create `src/policy/engine.ts`, its tests. Modify `src/agent/loop.ts` so every capability call passes through it.

**Requirements:** AP-1, FR-POL-2, FR-POL-3.

This is where AP-1 becomes real: the loop must be unable to invoke a capability without a decision. **Test through the loop, not by calling the engine directly.** P0.3's cancellation lesson applies exactly here.

Tests must prove: a denied call never reaches the capability; an allowed call does; an `ask` suspends the run pending an approval rather than proceeding or failing; the decision and its reason are persisted on the step row; and **an invalid policy prevents startup**.

**Self-attack:** bypass the engine in the loop and confirm a test fails.

---

### Task 4: Approvals in Slack

**Files:** create `src/approvals/store.ts`, `src/approvals/blockkit.ts`, their tests. Modify the Slack adapter to receive interactions.

**Requirements:** FR-APR-1 to FR-APR-7, FR-APR-10.

An approval request carries capability, human-readable description, exact target, tier, the escalation reason, the run and session identity, and the requester. Options: Approve, Deny, Approve-all-of-this-type-for-this-session with a TTL, and Edit-and-approve.

Tests must prove: **timeout defaults to deny-and-pause, never proceed**; a paused run posts an explicit waiting-on-you summary and is resumable; only an authorised approver can resolve, and an unauthorised attempt is rejected and logged; the highest tier requires typed confirmation rather than a click; three concurrent approvals resolve to the correct three actions; and every resolution is audited with actor, timestamp, and option.

**Self-attack:** make the timeout proceed instead of deny, and confirm a test fails; let an unauthorised principal approve, and confirm a test fails.

---

### Task 5: The engine hook bridge

**Read DEC-1 first.** This is the milestone's hardest task.

**Files:** create `src/engine/hook-bridge.ts`, its tests, and whatever hook script the engine requires.

The engine is a subprocess offering `PreToolUse` hooks, not an in-process callback. A hook must call back into Relay, block while a human decides in Slack, and allow or deny the tool call by its exit status.

Design decisions to make and record: how the hook addresses Relay, a local socket or an HTTP endpoint on loopback; how it authenticates, since anything on the machine could otherwise approve its own actions; what happens when Relay is unreachable, which **must fail closed**; and what bounds the wait, given a human may never answer.

Tests must prove: a hook denial actually prevents the tool call; a hook approval permits it; **Relay unreachable denies rather than allows**; a wait that exceeds its bound denies and reports; and the bridge cannot be driven by anything other than Relay.

**Self-attack:** make the unreachable case allow instead of deny, and confirm a test fails.

---

### Task 6: Kill switch

**Files:** create `src/killswitch.ts`, its tests.

**Requirements:** FR-POL-9.

Stops all runs, releases locks, aborts in-flight calls, and refuses new work until cleared. **Must take effect mid-action within five seconds, measured and asserted**, not merely eventually.

It must not queue behind the work it stops. P0.3 shipped exactly that bug: Stop serialised behind the run it was cancelling, and it took an adversarial test holding the queue open to prove the fix. Use the same test shape here.

Tests must prove: a kill during an in-flight capability halts it within five seconds, measured; new work is refused while engaged; clearing it restores service; and it is reachable from both the CLI and Slack.

**Self-attack:** route the kill through the normal queue and confirm the timing test fails.

---

### Task 7: Budget caps

**Files:** create `src/budget/meter.ts`, its tests. Wire into the loop.

**Requirements:** FR-POL-7, and the measured cost problem from P0.3.

Per-run, per-session, and per-principal-per-day caps in currency. Exceeding a cap **pauses the run and asks for authorisation** rather than failing silently. Use the engine's reported `total_cost_usd`, and consider `--max-budget-usd` as a second line of defence.

Tests must prove: each scope is independently enforced; a run hitting its cap pauses and posts an authorisation request; and approving raises the cap for that run only.

**Self-attack:** remove one scope's check and confirm a test fails.

## Self-Review of this plan

**Spec coverage.** FR-CAP-1 to 5 (Task 1), FR-POL-1 to 4 and 8 (Task 2), FR-POL-2 and 3 and AP-1 (Task 3), FR-APR-1 to 7 and 10 (Task 4), DEC-1's hook consequence (Task 5), FR-POL-9 (Task 6), FR-POL-7 (Task 7). Deliberately absent: FR-POL-11 dry-run, FR-POL-12 paranoid mode, FR-POL-13 policy simulation, FR-APR-8 standing approvals, and FR-APR-11 the waiting-on-you digest. Each is a refinement of a mechanism this milestone must first make exist.

**Known risk, stated.** Task 5 is the least certain, because it depends on the engine's hook contract rather than on Relay's own code. If the hook cannot block, or cannot be authenticated, the design changes and the implementer must stop and say so rather than inventing a weaker guarantee.
