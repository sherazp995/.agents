# Relay P0.2 Chat Contract and Slack Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Slack app that receives a mention, a DM, or a thread reply, turns it into a platform-neutral `ChatEvent`, and replies through one self-editing progress message, with tokens brokered from the Keychain and never written anywhere.

**Architecture:** One internal chat contract, two implementations. `SlackAdapter` wraps Bolt over Socket Mode; `MockAdapter` is an in-process fake. A single conformance suite runs against both, so the contract is proven rather than asserted. Secrets come from a `SecretProvider` seam whose macOS Keychain implementation is the only macOS-specific code in the milestone, satisfying NFR-10. Nothing in this milestone runs an agent loop or executes a task; a received message produces a canned reply. That is deliberate, so the adapter is proven before the orchestrator lands in P0.3.

**Tech Stack:** Everything from P0.1, plus `@slack/bolt` and `@slack/web-api`. No agent SDK yet.

## Prerequisite the operator must supply

This milestone can be built and fully tested without Slack credentials, because the conformance suite runs against the mock. **The final exit criterion cannot be met without them.** Before Task 6's real-workspace verification, the operator must:

1. Create a Slack app at `api.slack.com/apps` using the manifest Task 6 generates, which encodes exactly the FR-SLA-4 scopes so they cannot drift.
2. Enable Socket Mode and generate an app-level token with `connections:write`.
3. Install the app to the workspace, which is the one consent click.
4. Store both tokens in the Keychain under the names Task 1 defines.

Tasks 1 through 5 and 7 proceed without this. Task 6 stops and asks if the tokens are absent, and it must never fabricate a passing result from the mock.

## Global Constraints

Every task's requirements implicitly include these, copied verbatim from `docs/specs/2026-08-08-relay-requirements.md` v1.10 and the P0.1 roadmap.

- **FR-SLA-1:** Relay authenticates to Slack exclusively via a Slack App bot token plus an app-level token for Socket Mode. No password, email code, or interactive login is ever performed against Slack.
- **FR-SLA-3:** The bot posts under its own identity. No Relay message is ever attributed to the operator's account.
- **FR-SLA-4:** Requested bot scopes are minimal and enumerated: `app_mentions:read`, `chat:write`, `im:history`, `im:read`, `im:write`, `channels:history`, `groups:history`, `files:read`, `files:write`, `reactions:read`, `commands`.
- **FR-SLA-5:** Workspace-wide read scopes are not requested. No `search:read`, no `users:read.email`.
- **FR-SLA-6:** Tokens are stored in the Keychain via the secret broker, never in files, environment dumps, the database, logs, or the model context.
- **FR-SLA-8:** Socket Mode only. Relay exposes no public HTTP endpoint for Slack traffic.
- **FR-CA-1:** One internal chat contract that every adapter implements, with inbound `ChatEvent` and outbound `ChatAction`.
- **FR-CA-2:** Adapters declare their capabilities. The reporter degrades gracefully when one is absent.
- **FR-CA-3:** Adapter failures are retried with backoff and never lose a message. Outbound messages are queued durably.
- **FR-CA-4:** Each platform identity maps to a Relay principal. Unmapped users are ignored.
- **FR-SL-4:** Progress is a single self-editing message. A 30-step run produces one progress message, not 30.
- **FR-RPT-10:** No diffs, file bodies, raw logs, or long output in any chat surface.
- **FR-SEC-1 / FR-SEC-2:** No secret in the repository, the database, or any log. Secrets are brokered, never returned into a transcript.
- **AP-2:** All outside content is data, never instruction. Message text is never concatenated into a system prompt.
- **AP-8:** Every table carries `workspace_id` from its first migration.
- **NFR-10:** The core carries no macOS-specific dependency. macOS specifics live only behind an interface.
- **NFR-11:** One stated purpose per module, documented interface, independent tests.
- **Rule 45:** No dash used as sentence punctuation in prose, including code comments and commit messages.
- **Rule 41:** Cache test output to `tmp/test-cache/<name>.log`.
- **Rule 42:** Purely additive diffs run only their own narrow tests. The full suite runs at the gate.
- **Never `git add -A`.** Stage explicit paths. Reviewers doing revert-and-test use their own worktree.

### Task 5: Durable outbox and the progress reporter

**Files:**
- Create: `src/chat/outbox.ts`, `src/chat/progress.ts`, `test/chat/outbox.test.ts`, `test/chat/progress.test.ts`

**Interfaces:**
- Produces:
  - `class Outbox { constructor(pool, adapter, options?: { log?: Logger; maxAttempts?: number }); enqueue(action: ChatAction): Promise<string>; drain(): Promise<{ sent: number; failed: number }>; }` persisting to the `outbox` table so a crash loses nothing
  - `class ProgressReporter { constructor(adapter, ref, options?: { minIntervalMs?: number; log?: Logger }); update(text: string): Promise<void>; finish(text: string): Promise<void>; }` owning exactly one message

**Requirements this task satisfies:** FR-CA-3, FR-SL-4, FR-RPT-10.

Tests must assert:
- **Outbox:** an action survives a process restart, simulated by enqueueing with one instance and draining with a second against the same database. A failing `perform` is retried with backoff up to `maxAttempts`, then moves to a terminal failed state and is reported, never silently dropped. `drain` is safe to call concurrently without double-sending, which needs a row lock; prove it with two concurrent drains and assert exactly one send.
- **Progress:** thirty `update` calls produce exactly one `post` and at most a bounded number of `edit` calls, which is FR-SL-4's real requirement. The final `finish` always lands even if it arrives inside the throttle window, because a dropped final state is a lie about the run. Text longer than `maxMessageBytes` is summarised with a link placeholder rather than truncated silently, per FR-RPT-10.
