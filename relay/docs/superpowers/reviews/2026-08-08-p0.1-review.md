## Decide now, code in P0.2 (recorded, not dropped)

- I5 Redis retry budget is three attempts over ~300ms and `retryStrategy` returning non-number gives up permanently, so any Redis restart leaves a dead client. Fine for a one-shot probe, silent loss of lease for the machine lock. Split probe client from daemon client.
- I6 `DoctorChecks` is a fixed four-property type with a hand-wired body. FR-OBS-5 needs ten check classes and NFR-10 needs the macOS ones pluggable. Move to a `Check[]` registry over a context carrying the already-parsed config, which also removes the second config load and the fake connectivity-setup pseudo-check.
- I7 no secrets source exists, and P0.2 needs three (Slack bot token, signing secret, Anthropic key). The path of least resistance is the committed config file, which violates FR-SEC-1. Add a `getSecret(name)` seam over Keychain with an env fallback.
- I8 FR-OBS-1 holds only as a library. `createLogger` has no caller outside its own test, the CLI writes via `process.stdout.write`, and no module accepts a Logger. Decide the mechanism now, explicit parameter or AsyncLocalStorage, and use it in at least one module.
- Codex C-3 FR-OBS-1 identifiers are optional, so an unbound root logger can emit a line with none. Add a run-scoped logger factory requiring complete context when the run loop exists.
- I10 FR-POL-4's stated enforcement is the restart-only load path, but FR-POL-2 also requires hot reload with database overrides in the same phase. Hard-blocked origins must be structurally excluded from the reload and override paths.
- I11 FR-OBS-5 is overclaimed. The spec names ten dependency classes; the doctor reports four. Restate as the scoped subset it is.
- closeRedis uses disconnect(), dropping in-flight commands. Becomes a leaked physical machine lock once Redis backs the lock.
- The BEGIN|COMMIT|ROLLBACK word match blocks any PL/pgSQL trigger the run and session state machine may want.
