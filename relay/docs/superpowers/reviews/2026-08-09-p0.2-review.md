# Review — P0.2 milestone gate

**Verdict: PASS**, after one fix wave closed every finding the operator scoped in.

**Verdict at first gate pass: BLOCKED.** Two independent reviewers: a task reviewer on the Slack adapter, and Codex on the whole milestone diff.

Codex counts: blocker 2, high 7, medium 4, low 0. Task reviewer: 4 Important. Most findings carry an empirical reproduction rather than an argument.

Verified before review, by execution: 205 tests across 23 files with zero skips, `pnpm typecheck` exit 0, `pnpm build` clean, `relay doctor` nine checks ok against the live workspace, and a real DM producing a self-editing progress message.

## Blockers

1. **Any channel message becomes a task event.** `src/chat/slack/adapter.ts:558` filters only bots and subtypes, then dispatches every remaining message. FR-SL-2 permits channel entry only through `@relay` or a reply inside an existing Relay thread. As shipped, unrelated workspace conversation can trigger a computer-driving system. A test at `test/chat/slack/adapter.test.ts:392` explicitly pins the wrong behaviour.
2. **The durable outbox has no production caller.** `src/chat/progress.ts:176` performs posts and edits directly against the adapter, and `scripts/slack-smoke.ts` constructs the reporter with `SlackAdapter`. Repository-wide search finds no production construction of `Outbox`. FR-CA-3's zero-lost-message guarantee is therefore unwired: a crash or network failure loses the action.

## High

3. **Live adapter defaults every user to unmapped and dispatches anyway.** `adapter.ts:411` defaults `resolvePrincipalId` to `async () => null`, and the smoke path acts on the event regardless. FR-CA-4 requires an unmapped user to fail closed.
4. **Production config permits environment-sourced secrets.** `src/config/schema.ts:69` allows `provider: 'env'`. FR-SLA-6 requires Slack tokens in the Keychain and never in an environment dump.
5. **Slack's team id is emitted as Relay's workspace id.** `adapter.ts:213` assigns `team_id` to `ChatEvent.workspaceId`, but `workspaces.id` is a `uuid`. Passing it to `resolvePrincipal` or `Outbox.enqueue` cannot match and will fail on invalid uuid syntax.
6. **The outbox persists raw adapter error text to Postgres and logs it.** `src/chat/outbox.ts:247-272`. Codex reproduced `PERSISTED_LAST_ERROR:xoxb-PROOF-secret`, so a credential reaches the database. FR-SEC-1.
7. **A failed trailing edit is an unhandled rejection.** `src/chat/progress.ts:147` uses `void this.#dispatch(text)`. Codex reproduced `UNHANDLED:trailing-edit-failed`, which can terminate the process.
8. **Dedupe state is committed before principal resolution.** `adapter.ts:562` adds the key before `#buildChatEvent` awaits principal lookup, so a lookup failure makes Slack's retry hit the recorded key and the message is lost permanently.
9. **The smoke script logs inbound message text.** `scripts/slack-smoke.ts:82`. A DM containing a password is copied into logs, outside the broker and the scrubber.
10. **The adapter's logger does not scrub.** `src/obs/logger.ts:21-26` is bare pino with no redaction, and `scrubSecrets` is wired only into `src/doctor/run.ts`. A Bolt error carrying a token is written unredacted. Found by the task reviewer.
11. **File-upload self-loop is under-guarded and untested.** `file_share` is deliberately excluded from the ignored subtypes, and `FileShareMessageEvent` carries no `bot_id`, so only the `user === botUserId` check stands between Relay's own uploads and a self-loop. Untested. Found by the task reviewer.

## Medium

12. `ProgressReporter` never consults `capabilities.editMessage`, so an adapter honestly declaring it false fails after the first post rather than degrading. FR-CA-2.
13. Slack inbound conformance tests drive the wrapper's private handler rather than dispatching through the Bolt stub, so ordering and exactly-once tests would still pass if `SlackAdapter`'s own delivery broke.
14. `buildAppManifest()` omits the `app_home` block that the handwritten YAML gained this same milestone, so a consumer of the generator installs an app that cannot receive DMs. Found by both reviewers.
15. Real Slack call sites use an unbound root logger, and `createRunContext` has no production caller, so FR-OBS-1 remains a library-only assertion.

## OQ-3 resolved

The task reviewer settled it against Slack's documented `message_deleted` shape, where top-level `ts` differs from the deleted message's own ts. By the same shape `message_changed`'s top-level `ts` is the edit event's timestamp, not `message.ts`. **The controller's doubt was correct and the implementer's premise was false.** The regression test at `test/chat/slack/adapter.test.ts` asserts a same-ts collision real Slack will not produce, so it guards nothing while the genuine case goes untested. Codex independently discarded the same hypothesis for lack of a real-envelope proof, which is a fair objection to both sides; the documented shape is the best evidence available without capturing an envelope.

## Scope question for the operator

Findings 1, 2, 3, and 5 are not simply bugs. Each needs state or mapping that arguably belongs to P0.3: identifying an existing Relay thread needs session storage, wiring the outbox needs a dispatcher owner, failing closed on an unmapped principal needs principal provisioning, and mapping `team_id` to a workspace uuid needs a workspaces row. They are recorded here rather than silently deferred or silently expanded.


## Outcome

One fix wave, five commits, `8399648` through `e5b8bf8`. The test count moved from 205 to 223, so the new coverage is visible as a number rather than asserted.

A scoped re-review verdicted all ten in-scope findings ADDRESSED, proving six by revert-and-observe: disabling the outbox scrub put the raw secret back in `last_error`; restoring `void this.#dispatch` produced a genuine unhandled rejection; removing the `editMessage` check made the mock throw; removing the adapter's delivery queue failed the ordering test, which proves the conformance suite now exercises `SlackAdapter` rather than a wrapper; and breaking either side of the manifest parity test failed it independently. No new breakage, no weakened assertions.

The re-review also found the logger fix is **broader** than the fixer claimed: it scrubs nested object fields, `Error` messages, and `Error` stacks, because it operates on the fully serialised line. Understating coverage is the right direction to be wrong in.

## Two residual limits, stated rather than buried

- **`app_mention` text is not inspected.** `#isChannelEntryAllowed` accepts any `app_mention` envelope without checking the text actually contains the bot id. This is safe only because Slack guarantees that listener fires solely on genuine mentions. It is a trust boundary the code leans on deliberately, not an oversight, and it is worth revisiting if Slack's behaviour is ever in doubt.
- **Bot-authored `file_share` remains unproven against live Slack.** `FileShareMessageEvent` carries no `bot_id`, verified directly in `node_modules`, so `user === botUserId` is the only guard. It is real and tested. Whether Slack always sets `user` to the bot's own id on a self-upload was never captured from a real workspace, so the self-loop guard for uploads rests on a reasonable assumption rather than evidence.

Both belong in the same category as OQ-3 before it was resolved: settle them by capturing a real envelope when convenient.
